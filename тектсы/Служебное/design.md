# DP Barrel & Spirit — Design System

**Статус:** v1 — рабочая спецификация.  
**Назначение:** единый источник визуальных правил для сайта и AI-агентов.  
**Важно:** значения, помеченные `TBD / audit`, нельзя считать утверждёнными до сверки с текущим интерфейсом и CSS.

## 1. Визуальная концепция

- **Направление:** Dark Craft, Premium Craftsmanship, Artisan Workshop.
- **Ощущение:** натуральная древесина, мастерская, время, ручной труд, спокойная уверенность.
- **Главный визуальный актив:** реальные изделия и реальные фотографии.
- **Композиция:** выразительная, редакционная, с достаточным пространством и ясной иерархией.
- **Премиальность:** достигается материалом, светом, типографикой и деталями, а не количеством декоративных эффектов.

Избегать:
- чистого чёрного `#000000` как универсального фона;
- кислотных и чрезмерно насыщенных акцентов;
- glossy-эффектов и агрессивного glassmorphism;
- шаблонной e-commerce подачи;
- декоративных элементов, конкурирующих с фотографиями;
- AI-рендеров, искажающих или заменяющих реальные изделия без запроса.

## 2. Цветовые токены

Ниже приведены значения из существующих служебных рекомендаций. Это базовые кандидаты на токены; назначение и контраст необходимо проверить на реальном интерфейсе.

| Token | Значение | Роль |
|---|---|---|
| `--color-bg` | `#11100E` | Основной тёмный фон |
| `--color-surface` | `#141311` | Альтернативная поверхность |
| `--color-text-primary` | `#EDE8DF` | Основной светлый текст / заголовки |
| `--color-text-secondary` | `#D1CBC0` | Основной текст описаний |
| `--color-text-muted` | `#9E988F` | Приглушённый текст, если контраст достаточен |
| `--color-accent` | `#B87333` | Медный акцент |
| `--color-accent-soft` | `#D49B5B` | Тёплый акцент / hover-кандидат |
| `--color-border` | `#8A5A36` | Тёплая граница / разделитель |

### Правила использования

- Не используй все акцентные цвета одновременно в одном компоненте.
- Для текста на фоне проверяй фактический контраст; приглушённый цвет не должен ухудшать читаемость.
- Не вводи новые HEX-значения локально, если роль может быть закрыта существующим токеном.
- Если требуется новый цвет, объясни его роль и внеси его в таблицу.

- Проверь загрузку шрифтов и поведение fallback.

## 5. Карточки и медиа

Не существует одного универсального стиля карточки. Сначала классифицируй текущие компоненты, затем фиксируй параметры отдельно для каждого повторяемого типа.

Для каждого типа карточки документируй:
- назначение и компонент;
- соотношение сторон;
- радиус;
- рамку и её цвет;
- внутренние отступы;
- поведение изображения (`object-fit`, позиция кадрирования);
- заголовок, описание и метаданные;
- hover, active и focus-visible;
- мобильное поведение.

- Не менять пропорции реального изделия ради декоративного кадра.

## 6. Разделители и переходы секций

Используй небольшой согласованный набор:

1. **Тонкая линия** — для структурного разделения связанных областей.
2. **Смена поверхности** — когда нужна граница между секциями без линии.
3. **Медийный переход** — фотография или видео, если это поддерживает историю бренда.

Для линий:
- толщина: TBD / audit;
- цвет: токен `--color-border` или другой утверждённый токен;
- прозрачность: TBD / audit;
- отступ от контента: TBD / audit.

Не добавляй разделитель автоматически в каждый блок. Он должен иметь композиционную функцию.

## 7. Кнопки и ссылки

Для каждого повторяемого варианта зафиксировать:
- высоту и горизонтальные отступы;
- радиус;
- шрифт, размер и вес;
- цвет текста, фон и border;
- hover / active / focus-visible / disabled;
- минимальную удобную область на touch.

Не создавать визуально интерактивный элемент, если он не выполняет действие. У всех ссылок и кнопок должно быть ясное назначение.

## 8. Поверхности, рамки и тени

- Тени должны быть мягкими и подчиняться освещению изображения.
- Не использовать тяжёлую тень для каждого блока.
- Рамки должны помогать структуре, а не обводить всё подряд.
- Не добавлять glassmorphism как универсальное оформление.
- Любой декоративный overlay должен сохранять читаемость и достоверность фотографии.

## 9. Responsive

Документируй поведение, а не только набор пикселей.

Контрольные viewport для проверки:
- mobile: `375×812`, `390×844`;
- tablet: `768×1024`, `1024×768`;
- desktop: `1440×900`.

Проверяй:
- отсутствие горизонтального overflow;
- отсутствие обрезки заголовков и карточек;
- корректность порядка контента;
- размеры текста и кнопок;
- кадрирование фото/видео;
- работу навигации и интерактивных элементов.

Если viewport недоступен, отмечай его как непроверенный.

## 10. Доступность

- Используй семантические элементы HTML.
- Интерактивные элементы должны работать с клавиатуры.
- Сохраняй видимый `focus-visible`.
- Проверяй контраст текста.
- Учитывай `prefers-reduced-motion`.
- Не передавай смысл только цветом или движением.

## 11. Добавление новых правил

Если в системе отсутствует нужное значение:
1. Изучи существующие компоненты и стили.
2. Определи, является ли решение повторяемым.
3. Предложи токен или паттерн.
4. Проверь его на desktop и mobile.
5. После согласования внеси в этот документ и код.

Не выдавай временное локальное решение за утверждённую дизайн-систему.
