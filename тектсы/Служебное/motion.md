# DP Barrel & Spirit — Motion Guidelines

**Статус:** v1 — принципы и рабочие ограничения. Конкретные параметры уточняются после аудита текущих анимаций.

## 1. Принцип движения

Анимации должны поддерживать историю бренда и направлять внимание, а не демонстрировать возможности библиотеки.

Характер движения:
- спокойный;
- плавный;
- предсказуемый;
- без резких bounce и случайных колебаний;
- не мешающий чтению, навигации и взаимодействию.

Приоритет: функциональная ясность → производительность → эстетика.

## 2. Категории

| Категория | Примеры | Что требуется описать |
|---|---|---|
| Micro-interaction | hover кнопки, ссылка, focus | duration, easing, изменение |
| Reveal | появление заголовка/текста/фото | duration, offset, delay, trigger |
| Section transition | переход между крупными блоками | принцип, слои, scroll-взаимодействие |
| Scroll-linked | sticky, parallax, progress | диапазон, пределы, fallback |
| Smooth scrolling | Lenis или аналог | область действия, совместимость, reduced motion |
| Loading | загрузка медиа/шрифта | placeholder, смена состояния, layout stability |

Не применять одну анимацию ко всем категориям без проверки.

## 3. Предварительные ориентиры таймингов

Это стартовые диапазоны для проверки, а не уже утверждённые значения. Их нужно испытать на текущем сайте.

| Сценарий | Предварительный диапазон |
|---|---:|
| Hover / UI feedback | 150–300 ms |
| Небольшой reveal | 350–650 ms |
| Появление крупного изображения | 500–900 ms |
| Крупный section transition | 700–1200 ms, если оправдано |
| Stagger между текстовыми элементами | 50–120 ms |

Не задерживай появление важного контента настолько, чтобы пользователь ждал анимацию вместо чтения. Избегай длинных последовательностей с большим количеством элементов.

## 4. Easing

Предпочтение — спокойным ease-out / cubic-bezier кривым без bounce.

Рекомендуемый стартовый кандидат из имеющихся проектных рекомендаций:
`cubic-bezier(0.16, 1, 0.3, 1)`

Не применяй его автоматически к каждой анимации. Hover, scroll-linked движение и reveal могут требовать разных кривых.

## 5. Reveal и появление текста

- Сохраняй текст доступным для assistive technologies независимо от анимации.
- Не скрывай критически важный контент навсегда при сбое JavaScript.
- Не запускай reveal повторно при каждом небольшом движении scroll без необходимости.
- Не используй большие смещения текста, если они ухудшают чтение.
- Stagger должен быть коротким и умеренным.
- Учитывай reduced motion: отключай или существенно сокращай движение.

## 6. Scroll-linked эффекты и sticky

Для каждого эффекта документируй:
- какой элемент управляет движением;
- диапазон scroll;
- что происходит при быстрой прокрутке;
- поведение при resize;
- мобильный вариант;
- fallback при отключённом motion;
- влияние на sticky/fixed элементы и scroll restoration.

Не создавай несколько независимых систем, одновременно управляющих прокруткой одного участка.

## 7. Smooth scrolling и Lenis

Smooth scrolling — отдельное изменение поведения всей страницы, а не обычный декоративный эффект.

Перед добавлением Lenis или аналога:
1. Определи, какую проблему пользовательского опыта он решает.
2. Проверь нативную прокрутку, якоря и текущие scroll-анимации.
3. Проверь sticky/fixed элементы, модальные окна и блокировку scroll.
4. Проверь touch/mobile и клавиатурную навигацию.
5. Проверь `prefers-reduced-motion`.
6. Оцени нагрузку, синхронизацию и возможные конфликты.
7. Не добавляй библиотеку, если нативное поведение уже подходит.

Не комбинируй несколько smooth-scroll решений. Не делай Lenis обязательным для проекта.

## 8. Библиотеки

Выбор реализации зависит от задачи:
- CSS transitions/animations — для простых состояний;
- текущая motion-библиотека — если её возможности подходят;
- Lenis или аналог — только для отдельно обоснованного smooth-scroll;
- новая зависимость — после проверки, что существующий стек не закрывает задачу.

Не переписывай эффект с одной библиотеки на другую без функциональной или технической причины.

## 9. Производительность и доступность

- Избегай ненужной анимации layout-свойств.
- По возможности предпочитай трансформации и opacity, но не считай их автоматической гарантией производительности.
- Не запускай бесконечные анимации без смысловой необходимости.
- Проверяй на реальных viewport и устройствах, если доступно.
- Учитывай `prefers-reduced-motion`.
- Убедись, что анимация не препятствует взаимодействию и не вызывает layout shift.

## 10. Проверка и фиксация параметров

Для утверждённого motion-паттерна записывай:
- название и назначение;
- реализацию / компонент;
- trigger;
- duration;
- delay / stagger;
- easing;
- offset / transform;
- reduced-motion fallback;
- viewport, на котором проверено.

Не фиксируй значения как окончательные только на основании вкусовой оценки или чтения кода. Сначала проверь отрендеренный результат.
