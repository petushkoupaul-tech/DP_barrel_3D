# DP Barrel & Spirit — рабочий протокол агента

Этот документ дополняет корневой `AGENTS.md`. Он фиксирует процедуру проверки, а не визуальные правила.

## 1. До изменений

1. Установи корень проекта и проверь, что работаешь в нужном репозитории.
2. Проверь ветку, `git status` и diff.
3. Зафиксируй пользовательские изменения, которые нельзя затронуть.
4. Найди связанные компоненты, стили, assets и зависимости.
5. Для визуальной задачи зафиксируй исходное состояние, если нужна сравнительная проверка.
6. Сформулируй ограниченный scope: какие файлы ожидается менять и какие не затрагивать.

## 2. Локальный сервер

- Сначала проверь, запущен ли dev-сервер проекта.
- Не запускай второй сервер автоматически.
- Используй канонический URL `http://localhost:3000`, если конфигурация не задаёт другое.
- Если порт занят, выясни процесс и его принадлежность.
- Не завершай процессы другого проекта или с неясной принадлежностью.
- Не останавливай Node.js целиком по имени процесса.
- Запускай сервер из корня проекта.
- После проверки не оставляй дополнительные серверы, запущенные для задачи, если они больше не нужны.

Если доступные инструменты не позволяют достоверно установить процесс, не вмешивайся и сообщи о блокере.

## 3. Браузерная проверка

Для задачи, изменяющей интерфейс:
1. Открой точный URL проекта.
2. Убедись, что отображается актуальный экземпляр приложения.
3. Проверь затронутую секцию после обычной загрузки и hard reload, если кэш может влиять на результат.
4. Получи скриншот или другой прямой результат browser inspection.
5. Если доступны DevTools, проверь фактические DOM/computed styles, overflow, stacking, размеры и сетевые/консольные ошибки.
6. Проверь responsive viewport, релевантные задаче.

Общие контрольные viewport:
- `375×812`;
- `390×844`;
- `768×1024`;
- `1024×768`;
- `1440×900`.

Не обязательно выполнять полный аудит всех секций для локального изменения, не затрагивающего их.

## 4. Если браузер недоступен

- Не заявляй о визуальной проверке.
- Зафиксируй, на каком этапе инструмент недоступен и какую ошибку вернул.
- Выполни доступные проверки: build, lint, тесты, HTTP-ответ, Playwright или другой уже установленный инструмент.
- Не устанавливай новые пакеты и не меняй browser setup без необходимости.
- Явно укажи, что альтернативные проверки не заменяют визуальный осмотр.

## 5. Завершение

Отчёт должен содержать:
- изменённые файлы;
- краткое описание изменений;
- выполненные проверки и фактические результаты;
- непроверенные области и блокеры;
- Git status.

Commit, push и deploy выполняются только по прямому запросу.
